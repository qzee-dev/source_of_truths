### 2. **AWS_ROLE_ARN**

**Where:** Multiple workflows
- `release.yml` line 211
- `deploy-dev.yaml` line 163
- `deploy-staging.yaml` line 230
- `deploy-production.yaml` line 277

**Workflow usage:**
```yaml
role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
```

**Type:** Plain text  
**Value:** IAM role ARN (e.g., `arn:aws:iam::123456789012:role/GitHubActionsRole`)  
**Scope:** Repository level + Environment level  

**How to create:**

1. **Create IAM Role in AWS:**
   ```bash
   # Trust policy for GitHub OIDC
   cat > trust-policy.json <<EOF
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Principal": {
           "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com"
         },
         "Action": "sts:AssumeRoleWithWebIdentity",
         "Condition": {
           "StringEquals": {
             "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
           },
           "StringLike": {
             "token.actions.githubusercontent.com:sub": "repo:Coreinfra-Labs/fintech-platform:*"
           }
         }
       }
     ]
   }
   EOF
   
   aws iam create-role \
     --role-name GitHubActionsRole \
     --assume-role-policy-document file://trust-policy.json
   ```

2. **Attach policies:**
   ```bash
   # ECR access
   aws iam attach-role-policy \
     --role-name GitHubActionsRole \
     --policy-arn arn:aws:iam::aws:policy/AmazonEC2ContainerRegistryPowerUser
   
   # EKS access
   aws iam attach-role-policy \
     --role-name GitHubActionsRole \
     --policy-arn arn:aws:iam::aws:policy/AmazonEKSClusterPolicy
   ```

3. **Get the ARN:**
   ```bash
   aws iam get-role --role-name GitHubActionsRole \
     --query 'Role.Arn' --output text
   ```

4. **Add to GitHub Secrets:**
   - Settings → Secrets and variables → Actions → New repository secret
   - Name: `AWS_ROLE_ARN`
   - Value: `arn:aws:iam::123456789012:role/GitHubActionsRole`

### 3. **RELEASE_REPOSITORY_TOKEN**

**Where:** `deploy-dev.yaml` line 49
```yaml
github-token: ${{ secrets.RELEASE_REPOSITORY_TOKEN }}
```

**Type:** GitHub Personal Access Token (PAT)  
**Scope:** Repository level  
**Permissions required:**
- `actions:read` — Read GitHub Actions artifacts
- `contents:read` — Read repository contents

**How to create:**

1. **Generate GitHub PAT:**
   - GitHub Profile → Settings → Developer settings → Personal access tokens → Tokens (classic)
   - Generate new token (classic)
   - Scopes: `actions:read`, `contents:read`
   - Copy the token

2. **Add to GitHub Secrets:**
   - Settings → Secrets and variables → Actions → New repository secret
   - Name: `RELEASE_REPOSITORY_TOKEN`
   - Value: `ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

---

### 4. **RELEASE_APP_ID & RELEASE_APP_PRIVATE_KEY**

**Where:** `deploy-staging.yaml` lines 53-54
```yaml
app-id: ${{ secrets.RELEASE_APP_ID }}
private-key: ${{ secrets.RELEASE_APP_PRIVATE_KEY }}
```

**Purpose:** GitHub App for cross-repository access (source repo + GitOps repo)

**Scope:** Repository level  

**How to create:**

1. **Create GitHub App:**
   - GitHub Profile → Settings → Developer settings → GitHub Apps → New GitHub App
   - Fill in:
     - App name: `fintech-release-automation`
     - Webhook: Uncheck (not needed)
     - Repository permissions:
       - `contents: read & write`
       - `actions: read`

2. **Generate private key:**
   - App details page → Private keys → Generate a private key
   - Copy the PEM content

3. **Get App ID:**
   - App ID is shown on the app details page

4. **Add to GitHub Secrets:**
   - Name: `RELEASE_APP_ID`
   - Value: `123456` (the numeric ID)
   
   - Name: `RELEASE_APP_PRIVATE_KEY`
   - Value: (paste the PEM private key, including `-----BEGIN RSA PRIVATE KEY-----` and `-----END RSA PRIVATE KEY-----`)

### 6. **ARGOCD_AUTH_TOKEN**

**Where:** `deploy-staging.yaml` line 513, `deploy-production.yaml` line 553
```yaml
env:
  ARGOCD_AUTH_TOKEN: ${{ secrets.ARGOCD_AUTH_TOKEN }}
```

**Type:** Argo CD authentication token  
**Scope:** Repository level + Environment level (staging, production)  

**How to create:**

1. **Generate token in Argo CD:**
   ```bash
   # Port-forward to Argo CD
   kubectl port-forward -n argocd svc/argocd-server 8080:443
   
   # Login with admin
   argocd login localhost:8080 --username admin --password <initial-admin-password>
   
   # Create a service account or use existing
   argocd account generate-token --account github-actions
   ```

2. **Store token securely:**
   - Settings → Secrets and variables → Actions → New repository secret
   - Name: `ARGOCD_AUTH_TOKEN`
   - Value: (paste the generated token)

3. **Also add as Environment secret:**
   - Settings → Environments → staging → Add secret
   - Name: `ARGOCD_AUTH_TOKEN`
   - Value: (same token)
   
   - Settings → Environments → production → Add secret
   - Name: `ARGOCD_AUTH_TOKEN`
   - Value: (same token)

## 📍 Environment-Specific Secrets

Some secrets should be added at **environment level** for extra protection:

### **Dev Environment** (if used)
- No additional secrets needed (inherits repository secrets)

### **Staging Environment**
- **ARGOCD_AUTH_TOKEN** (environment-level override recommended)
- **ARGOCD_SERVER** (environment variable, not secret)

Add at: Settings → Environments → staging → Environment secrets

### **Production Environment**
- **ARGOCD_AUTH_TOKEN** (environment-level override recommended)
- **ARGOCD_SERVER** (environment variable, not secret)
- **AWS_ROLE_ARN** (production-specific role recommended)

Add at: Settings → Environments → production → Environment secrets

## 🔐 Security Best Practices

1. **Use GitHub App over PAT when possible** — GitHub App tokens are more secure and scoped
2. **Rotate secrets regularly** — Especially ARGOCD_AUTH_TOKEN
3. **Environment secrets for sensitive stages** — production should have its own secrets
4. **Use OIDC for AWS** — Avoids long-lived AWS credentials
5. **Restrict GitHub App permissions** — Use minimal required scopes
6. **Audit access logs** — Monitor who's using these secrets
