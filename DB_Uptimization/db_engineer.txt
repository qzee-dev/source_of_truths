# Complete Database Optimization Analysis & Runbook

## Current Schema Analysis

### Current State
```
✅ Good Practices Found:
- Schemas separation (users, wallets, transactions, ledger, fraud)
- UUID primary keys
- JSONB for flexible metadata
- Basic indexing on common queries
- Timestamps for audit trails
- Foreign key relationships

❌ Optimization Issues Found:
- Missing composite indexes (compound keys)
- No partitioning strategy for large tables
- Inefficient index design for common queries
- Missing partial indexes for filtered queries
- No connection pooling configuration
- Missing query optimization hints
- No materialized views for reporting
- Suboptimal data types in some columns
- Missing covering indexes
- No constraint on numeric precision
```

## Step-by-Step Database Optimization

### Step 1: Add Composite Indexes (Query Performance)

Create `migrations/001_add_composite_indexes.sql`:

```sql
-- Composite indexes for common query patterns

-- Users: filter by status and created_at
CREATE INDEX idx_users_status_created 
ON users.users(account_status, created_at DESC)
WHERE deleted_at IS NULL;

-- Wallets: find user wallets sorted by balance
CREATE INDEX idx_wallets_user_active 
ON wallets.wallets(user_id, is_frozen, balance DESC)
WHERE is_frozen = FALSE;

-- Transactions: find by user and status
CREATE INDEX idx_transactions_source_status 
ON transactions.transactions(source_wallet_id, status, created_at DESC)
WHERE status IN ('PENDING', 'PROCESSING');

CREATE INDEX idx_transactions_destination_created 
ON transactions.transactions(destination_wallet_id, created_at DESC);

-- Transactions: fraud/dashboard queries
CREATE INDEX idx_transactions_created_status 
ON transactions.transactions(created_at DESC, status)
WHERE created_at > NOW() - INTERVAL '30 days';

-- Ledger: account history queries
CREATE INDEX idx_ledger_account_created 
ON ledger.ledger_entries(account_id, created_at DESC);

-- Fraud alerts: recent high-risk alerts
CREATE INDEX idx_fraud_alerts_status_created 
ON fraud.fraud_alerts(status, created_at DESC)
WHERE status IN ('PENDING', 'FLAGGED');

-- Fraud alerts: user risk analysis
CREATE INDEX idx_fraud_alerts_user_created 
ON fraud.fraud_alerts(user_id, created_at DESC, risk_score DESC);
```

```sql
  ALTER COLUMN status TYPE VARCHAR(20);

-- Add CHECK constraints for better data validation

  ADD CONSTRAINT check_balance_non_negative 
    CHECK (balance >= 0),
  ADD CONSTRAINT check_available_balance 
    CHECK (available_balance >= 0 AND available_balance <= balance);

ALTER TABLE transactions.transactions
  ADD CONSTRAINT check_amount_positive 
    CHECK (amount > 0);

ALTER TABLE ledger.ledger_entries
  ADD CONSTRAINT check_debit_credit 
    CHECK ((debit > 0 AND credit = 0) OR (credit > 0 AND debit = 0));
```

### Step 3: Add Partial Indexes (Reduce Index Size)

Create `migrations/003_add_partial_indexes.sql`:

```sql
-- Only index active users (reduces index size by ~50%)
CREATE INDEX idx_users_active 
ON users.users(email)
WHERE deleted_at IS NULL AND account_status = 'ACTIVE';

-- Only index pending transactions (hot data)
CREATE INDEX idx_transactions_pending 
ON transactions.transactions(source_wallet_id, created_at DESC)
WHERE status = 'PENDING';

-- Only index recent fraud alerts
CREATE INDEX idx_fraud_alerts_recent 
ON fraud.fraud_alerts(user_id, risk_score DESC)
WHERE created_at > NOW() - INTERVAL '90 days'
  AND status != 'RESOLVED';

-- Only index non-frozen wallets
CREATE INDEX idx_wallets_active 
ON wallets.wallets(user_id, balance DESC)
WHERE is_frozen = FALSE;

-- Only index high-value transactions (for audit)
CREATE INDEX idx_transactions_high_value 
ON transactions.transactions(amount DESC, created_at DESC)
WHERE amount > 1000000;
```

### Step 6: Add Materialized Views (Reporting Performance)

Create `migrations/006_add_materialized_views.sql`:

```sql
-- Dashboard summary: cached view updated hourly
CREATE MATERIALIZED VIEW reporting.user_wallet_summary AS
SELECT 
  u.id AS user_id,
  u.email,
  COUNT(DISTINCT w.id) AS wallet_count,
  SUM(w.balance) AS total_balance,
  SUM(w.available_balance) AS total_available,
  COUNT(CASE WHEN w.is_frozen THEN 1 END) AS frozen_count,
  u.account_status,
  u.kyc_status,
  u.created_at
FROM users.users u
LEFT JOIN wallets.wallets w ON u.id = w.user_id
WHERE u.deleted_at IS NULL
GROUP BY u.id, u.email, u.account_status, u.kyc_status, u.created_at;

CREATE INDEX idx_user_wallet_summary_user_id ON reporting.user_wallet_summary(user_id);

-- Transaction metrics: daily stats
CREATE MATERIALIZED VIEW reporting.transaction_daily_metrics AS
SELECT 
  DATE(created_at) AS transaction_date,
  status,
  type,
  COUNT(*) AS transaction_count,
  SUM(amount) AS total_amount,
  AVG(amount) AS avg_amount,
  MIN(amount) AS min_amount,
  MAX(amount) AS max_amount,
  COUNT(DISTINCT source_wallet_id) AS unique_senders
FROM transactions.transactions
WHERE created_at > NOW() - INTERVAL '90 days'
GROUP BY DATE(created_at), status, type;

CREATE INDEX idx_transaction_metrics_date ON reporting.transaction_daily_metrics(transaction_date DESC);

-- Fraud dashboard: recent alerts
CREATE MATERIALIZED VIEW reporting.fraud_alert_summary AS
SELECT 
  DATE(created_at) AS alert_date,
  alert_type,
  status,
  COUNT(*) AS alert_count,
  AVG(risk_score) AS avg_risk_score,
  MAX(risk_score) AS max_risk_score,
  COUNT(DISTINCT user_id) AS affected_users
FROM fraud.fraud_alerts
WHERE created_at > NOW() - INTERVAL '30 days'
GROUP BY DATE(created_at), alert_type, status;

CREATE INDEX idx_fraud_summary_date ON reporting.fraud_alert_summary(alert_date DESC);
```

### Step 10: Add Application-Level Caching Strategy

Create `migrations/009_add_cache_keys.sql`:

```sql
-- Add columns for cache invalidation tracking
ALTER TABLE users.users ADD COLUMN IF NOT EXISTS cache_version INT DEFAULT 1;
ALTER TABLE wallets.wallets ADD COLUMN IF NOT EXISTS cache_version INT DEFAULT 1;
ALTER TABLE transactions.transactions ADD COLUMN IF NOT EXISTS cache_version INT DEFAULT 1;

-- Trigger to update cache version on changes
CREATE OR REPLACE FUNCTION invalidate_cache()
RETURNS TRIGGER AS $$
BEGIN
  NEW.cache_version = COALESCE(OLD.cache_version, 0) + 1;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Apply triggers
CREATE TRIGGER user_cache_invalidate BEFORE UPDATE ON users.users
  FOR EACH ROW EXECUTE FUNCTION invalidate_cache();

CREATE TRIGGER wallet_cache_invalidate BEFORE UPDATE ON wallets.wallets
  FOR EACH ROW EXECUTE FUNCTION invalidate_cache();

CREATE TRIGGER transaction_cache_invalidate BEFORE UPDATE ON transactions.transactions
  FOR EACH ROW EXECUTE FUNCTION invalidate_cache();
```

## Performance Monitoring Queries

Create `scripts/monitoring-queries.sql`:

```sql
-- 1. Find slow queries
SELECT 
  query,
  calls,
  total_time,
  mean_time,
  max_time
FROM pg_stat_statements
ORDER BY mean_time DESC
LIMIT 20;

-- 2. Index usage statistics
SELECT 
  schemaname,
  tablename,
  indexname,
  idx_scan,
  idx_tup_read,
  idx_tup_fetch
FROM pg_stat_user_indexes
ORDER BY idx_scan DESC;

-- 3. Unused indexes
SELECT 
  schemaname,
  tablename,
  indexname,
  idx_scan
FROM pg_stat_user_indexes
WHERE idx_scan = 0
ORDER BY pg_relation_size(indexrelid) DESC;

-- 4. Table sizes
SELECT 
  schemaname,
  tablename,
  pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) AS size
FROM pg_tables
WHERE schemaname NOT IN ('pg_catalog', 'information_schema')
ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;

-- 5. Cache hit ratio
SELECT 
  sum(heap_blks_read) as heap_read,
  sum(heap_blks_hit) as heap_hit,
  sum(heap_blks_hit) / (sum(heap_blks_hit) + sum(heap_blks_read)) as ratio
FROM pg_statio_user_tables;

-- 6. Transaction lock analysis
SELECT 
  datname,
  usename,
  application_name,
  query,
  query_start,
  state
FROM pg_stat_activity
WHERE state != 'idle'
ORDER BY query_start;

-- 7. Missing indexes (based on seq scans)
SELECT 
  schemaname,
  tablename,
  seq_scan,
  seq_tup_read,
  seq_scan - idx_scan AS seq_tup_excess
FROM pg_stat_user_tables
WHERE seq_scan > 10000
ORDER BY seq_scan - idx_scan DESC;

-- 8. Table bloat check
SELECT 
  current_database(),
  schemaname,
  tablename,
  ROUND(100.0 * (CASE WHEN otta = 0 THEN 0 
    ELSE sml.relpages - otta END) / sml.relpages, 2) AS table_waste_ratio
FROM (
  SELECT
    schemaname,
    tablename,
    relpages,
    CEIL((cc::float) / (8192.0 / 4.0)) AS otta
  FROM pg_class c
  JOIN pg_namespace n ON n.oid = c.relnamespace
  WHERE n.nspname NOT IN ('pg_catalog', 'information_schema')
) AS sml
ORDER BY table_waste_ratio DESC;
```

## Implementation Runbook

### Phase 1: Pre-Production Setup (Week 1)

```bash
# 1. Backup current database
pg_dump fintech_db > backup_before_optimization.sql

# 2. Apply optimization migrations sequentially

# migrations/002_optimize_data_types.sql
# migrations/003_add_partial_indexes.sql
# migrations/004_add_covering_indexes.sql
```
