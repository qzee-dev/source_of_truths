## Part 3: Server OS & BIOS Tuning

### BIOS Settings Optimization

```bash
# Login to BIOS/UEFI during server boot (usually F2 or Delete key)

1. CPU Settings:
   ✅ Enable Hyper-Threading
   ✅ Enable Turbo Boost / XE (frequency scaling)
   ✅ Disable C-States (power management) for consistent performance
   ✅ Disable P-States (for predictable latency)
   ✅ Set CPU frequency to Maximum (disable dynamic scaling)
   ✅ Enable VT-x/AMD-V (virtualization)
   ✅ Set NUMA mode: Enabled (for large RAM systems)

2. Memory Settings:
   ✅ Enable XMP/DOCP (memory speed optimization)
   ✅ Set memory to max supported speed
   ✅ Enable ECC if available
   ✅ Disable memory power saving

3. Storage Settings:
   ✅ Set AHCI mode for SSD
   ✅ Disable write caching during battery (redundant PSU anyway)
   ✅ Enable NCQ (Native Command Queuing)
   ✅ Disable IDE support

4. Network Settings:
   ✅ Enable network boot priority
   ✅ Disable onboard WiFi (use Ethernet only)
   ✅ Set network to full duplex

5. Power Settings:
   ✅ Disable CPU power management
   ✅ Disable PCI power management
   ✅ Set power supply redundancy: Active
```

## Part 5: Storage Optimization

### SSD Configuration

```bash
# 1. Check SSD info
lsblk
nvme list
smartctl -a /dev/nvme0n1

# 2. Enable SSD trim/discard
sudo systemctl enable fstrim.timer
sudo systemctl start fstrim.timer

# 3. Optimize I/O scheduler for NVMe
# Add to /etc/default/grub:
GRUB_CMDLINE_LINUX="elevator=none"  # Use deadline for SATA SSD

sudo grub-mkconfig -o /boot/grub/grub.cfg
sudo reboot

# 4. Check I/O scheduler
cat /sys/block/nvme0n1/queue/scheduler

# 5. Enable write-back cache (if UPS present)
hdparm -W1 /dev/sda

# 6. Disable disk write protect on SSD (safer with UPS)
hdparm -w /dev/nvme0n1

# 7. Monitor SSD health
sudo nvme smart-log /dev/nvme0n1
```

### Partition Strategy for Database

```bash
# Optimal layout for PostgreSQL:
# 1. OS partition        (sda1)  - 100 GB  - ext4
# 2. Data partition      (sda2)  - 1.5 TB  - ext4 (data files)
# 3. WAL partition       (sda3)  - 500 GB  - ext4 (transaction logs)
# 4. Backup partition    (sda4)  - 2 TB    - ext4 (backups)

# Create partitions (example with fdisk):
sudo fdisk /dev/nvme0n1

# Format partitions
sudo mkfs.ext4 -F -E stride=2,stripe-width=4 /dev/nvme0n1p1
sudo mkfs.ext4 -F -E stride=2,stripe-width=4 /dev/nvme0n1p2
sudo mkfs.ext4 -F -E stride=2,stripe-width=4 /dev/nvme0n1p3

# Mount with optimizations
sudo mount -o noatime,nodiratime,data=ordered,barrier=1 /dev/nvme0n1p2 /var/lib/postgresql/data
sudo mount -o noatime,nodiratime,data=ordered,barrier=1 /dev/nvme0n1p3 /var/lib/postgresql/wal

# Add to /etc/fstab:
/dev/nvme0n1p2 /var/lib/postgresql/data ext4 defaults,noatime,nodiratime,data=ordered 0 2
/dev/nvme0n1p3 /var/lib/postgresql/wal ext4 defaults,noatime,nodiratime,data=ordered 0 2
```

## Part 6: CPU & Memory Optimization

### CPU Isolation (Linux)

```bash
# 1. Disable CPU frequency scaling
echo "powersave" | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor

# Or set to performance:
echo "performance" | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor

# 2. Pin processes to specific CPUs
# Add to /etc/security/limits.conf:
postgres soft memlock unlimited
postgres hard memlock unlimited

# 3. Use taskset to bind PostgreSQL to CPUs
sudo taskset -p -c 0-31 $(pgrep postgres)

# 4. Disable CPU C-states (kernel tuning)
# Add to /etc/default/grub:
GRUB_CMDLINE_LINUX="idle=poll processor.max_cstate=1"

sudo grub-mkconfig -o /boot/grub/grub.cfg
```

### Memory Optimization

```bash
# 1. Check NUMA nodes
numactl --hardware

# 2. Allocate memory per NUMA node
numactl -m 0 -N 0 /usr/lib/postgresql/15/bin/postgres

# 3. Disable swap (if you have enough RAM)
sudo swapoff -a
# Remove swap entry from /etc/fstab

# 4. Monitor memory
free -h
cat /proc/meminfo

# 5. Set memory limits for PostgreSQL
# In /etc/security/limits.conf:
postgres soft nofile 65535
postgres hard nofile 65535
postgres soft nproc 32768
postgres hard nproc 32768
postgres soft core unlimited
postgres hard core unlimited
```

## Part 7: Network Optimization

### Network Interface Tuning

```bash
# 1. Enable jumbo frames (9000 MTU) - only if network supports
sudo ip link set dev eth0 mtu 9000

# Or add to /etc/network/interfaces:
auto eth0
iface eth0 inet static
    address 192.168.1.10
    netmask 255.255.255.0
    gateway 192.168.1.1
    mtu 9000

# 2. Enable network bonding (dual NIC for redundancy)
# Create /etc/network/interfaces.d/bond0:
auto bond0
iface bond0 inet static
    address 192.168.1.10
    netmask 255.255.255.0
    gateway 192.168.1.1
    bond-slaves eth0 eth1
    bond-mode active-backup
    bond-miimon 100
    mtu 9000

# 3. Configure TCP offloading
ethtool -K eth0 gso on gro on tso on

# 4. Increase NIC RX/TX ring buffers
ethtool -G eth0 rx 4096 tx 4096

# 5. Monitor network
ethtool -S eth0
```

### Storage Network (for SAN/NAS)

```bash
# For iSCSI connections:
# 1. Install iSCSI initiator
sudo apt-get install open-iscsi

# 2. Configure iSCSI for performance
# Edit /etc/iscsi/iscsid.conf:
node.session.timeo.replacement_timeout = 120
node.session.initial_login_retry_max = 8
node.session.auth.chap_algs = SHA3-256,SHA256,MD5
node.tcp_keepalives_idle = 300
node.tcp_keepalives_count = 5
node.tcp_keepalives_interval = 30

# 3. Connect to iSCSI target
sudo iscsiadm -m discovery -t sendtargets -p 192.168.1.100:3260
sudo iscsiadm -m node --login
```

## Part 9: Monitoring Server Performance

### Install Monitoring Tools

```bash
# 1. Install system monitoring
sudo apt-get install htop iotop nethogs systat collectd

# 2. Monitor CPU
htop
# Look for: CPU usage, context switches, load average

# 3. Monitor I/O
iotop -o
iostat -x 1
# Look for: await, r_await, w_await, iops, throughput

# 4. Monitor Memory
free -h
vmstat 1
# Look for: cache, buffer, swap, page faults

# 5. Monitor Network
nethogs
iftop
# Look for: throughput, packet loss, errors

# 6. Monitor Disk
df -h
du -sh /var/lib/postgresql/*
lsblk
```

### Performance Baseline Queries

```bash
# Monitor query performance
psql fintech_db -c "
SELECT 
    query,
    calls,
    total_time,
    mean_time,
    max_time
FROM pg_stat_statements
ORDER BY mean_time DESC
LIMIT 10;
"

# Check cache hit ratio
psql fintech_db -c "
SELECT 
    sum(heap_blks_hit) / (sum(heap_blks_hit) + sum(heap_blks_read)) AS ratio
FROM pg_statio_user_tables;
"

# Monitor connections
psql fintech_db -c "
SELECT 
    usename,
    state,
    count(*)
FROM pg_stat_activity
GROUP BY usename, state;
"

# Monitor index usage
psql fintech_db -c "
SELECT 
    schemaname,
    tablename,
    indexname,
    idx_scan
FROM pg_stat_user_indexes
ORDER BY idx_scan DESC;
"
```

    (SELECT count(*) FROM pg_stat_activity) as connections,
    (SELECT sum(calls) FROM pg_stat_statements) as total_queries,
    (SELECT sum(heap_blks_hit)::float / (sum(heap_blks_hit) + sum(heap_blks_read))::float 
     FROM pg_statio_user_tables) as cache_ratio;
\"'
"

echo "Monitoring started in tmux sessions:"
tmux list-sessions

## Answer to Your Question

**YES, physical infrastructure optimization has MASSIVE impact:**

- **CPU**: Determines max TPS (transactions per second)
- **RAM**: Determines cache hit ratio (memory = speed)
- **SSD**: Determines I/O speed (NVMe = 10x faster than SATA)
- **Network**: Determines replication lag (25Gbps = critical for HA)
- **OS Tuning**: Can give **40-60% improvement** without hardware changes

**Most impactful upgrades (ROI):**
1. **NVMe SSD** instead of SATA → **5x faster I/O**
2. **RAM upgrade** 64GB→512GB → **80%+ cache hit ratio**
3. **CPU cores** 8→60 cores → **Parallel query handling**
4. **Network** 1Gbps→25Gbps → **Replication, backups**
5. **OS tuning** → **40% immediate improvement**

For a fintech platform processing millions of transactions, infrastructure optimization is **NOT optional** — it's **critical for stability and profitability**.
