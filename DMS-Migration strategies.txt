# Hybrid Database Migration to AWS RDS with DMS and Site-to-Site VPN

I designed and implemented a production-oriented hybrid database migration architecture to move an on-premises PostgreSQL database to Amazon RDS with minimal downtime. The solution used AWS Database Migration Service (DMS) for continuous replication and a Site-to-Site VPN to establish secure private connectivity between the on-prem environment and AWS.

The architecture followed AWS landing zone best practices by separating the network, database, and migration layers in a private VPC. The AWS environment included dedicated app, database, and DMS subnets to maintain isolation and reduce operational risk. The database tier was placed in private subnets, without public access, and was protected by security groups and route tables designed for strict least-privilege access. The DMS replication instance was also isolated in a private subnet and used a dedicated security group to communicate only with the source on-prem database and the target RDS instance.

To ensure secure hybrid connectivity, the solution used AWS Virtual Private Gateway and Customer Gateway with IPsec Site-to-Site VPN, configured with strong production-grade encryption, integrity, and DH group settings. This created a private path between the on-prem network and AWS without exposing database traffic to the public internet. Route tables were configured so only the required on-prem CIDR ranges passed over the VPN tunnel, and firewall rules were restricted to the required ports and protocols.

The target RDS instance was configured for production readiness with Multi-AZ deployment, encryption at rest, automatic backups, parameter tuning, performance monitoring, and private-only networking. DMS was configured for full load and change data capture so that the database could be replicated continuously before final cutover. Data validation was performed before the final switch, and the application cutover was staged to keep downtime as low as possible. The migration runbook included rollback procedures, validation checks, and a clear post-cutover monitoring plan.

This project emphasized production best practices such as private networking, strong security controls, encryption, isolated Terraform state, and operational readiness. It also highlighted the importance of backend state separation to reduce blast radius and improve deployment safety. The overall design was structured to support a controlled migration, secure hybrid connectivity, and reliable production cutover without exposing the environment to unnecessary risk.

This project demonstrates strong cloud architecture skills across networking, database migration, AWS security, private connectivity, automation, and production operations. It is a strong example of enterprise-grade hybrid cloud design and migration planning.
