## 1. Kafka Architecture Summary

The fintech platform implements a **partially event-driven microservices architecture** using Kafka for inter-service communication. However, the implementation is **incomplete and inconsistent**:

- **Transaction flow**: Initiated via REST API → Published to Kafka topic `transactions` → Consumed by multiple services
- **Event propagation**: `transaction-service` publishes to `transaction-completed` topic after ledger settlement
- **Kafka usage is asymmetric**: Some services only produce, some only consume; wallet-service has both capabilities but doesn't use them
- **Payment and wallet services do NOT participate in Kafka event flows** despite having Kafka infrastructure initialized
- **HTTP/REST remains the primary inter-service communication mechanism** (e.g., transaction-service calls fraud-service via HTTP; notification-service has no actual event handling)
