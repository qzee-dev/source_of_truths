# 4. Docker Compose Configuration

Create a dedicated section for your `docker-compose.yml`.

For example:

```yaml
services:
  kafka:
    image: apache/kafka:3.8.0

    ports:
      - "9092:9092"

    environment:
      KAFKA_NODE_ID: "1"

      KAFKA_PROCESS_ROLES: "broker,controller"

      KAFKA_CONTROLLER_LISTENER_NAMES: "CONTROLLER"

      KAFKA_LISTENERS: "INTERNAL://:29092,EXTERNAL://:9092,CONTROLLER://:9093"

      KAFKA_ADVERTISED_LISTENERS: "INTERNAL://kafka:29092,EXTERNAL://localhost:9092"

      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: "INTERNAL:PLAINTEXT,EXTERNAL:PLAINTEXT,CONTROLLER:PLAINTEXT"

      KAFKA_INTER_BROKER_LISTENER_NAME: "INTERNAL"

      KAFKA_CONTROLLER_QUORUM_VOTERS: "1@kafka:9093"

      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: "1"

      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: "1"

      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: "1"

      KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: "0"

      KAFKA_NUM_PARTITIONS: "3"
```

**Important:** Keep the exact configuration you're actually using in Git as the source of truth. The Confluence page should explain it rather than becoming a second, potentially outdated configuration source.

# 5. Configuration Explanation

This is one of the most useful sections.

Create a table:

| Variable | Meaning |
|---|---|
| `KAFKA_NODE_ID` | Unique Kafka node ID |
| `KAFKA_PROCESS_ROLES` | Runs Kafka as broker and controller |
| `KAFKA_LISTENERS` | Interfaces/ports Kafka listens on |
| `KAFKA_ADVERTISED_LISTENERS` | Addresses clients receive for connecting |
| `KAFKA_CONTROLLER_LISTENER_NAMES` | Listener used by KRaft controllers |
| `KAFKA_CONTROLLER_QUORUM_VOTERS` | Defines the KRaft controller quorum |
| `KAFKA_INTER_BROKER_LISTENER_NAME` | Listener used for broker communication |
| `KAFKA_NUM_PARTITIONS` | Default number of partitions for new topics |

This turns the page from a **copy/paste tutorial** into documentation you can actually use later.

# 8. Topic Management

## Create Topic

```bash
docker exec kafka \
  /opt/kafka/bin/kafka-topics.sh \
  --create \
  --topic test-topic \
  --bootstrap-server localhost:9092 \
  --partitions 3 \
  --replication-factor 1
```

```bash

  /opt/kafka/bin/kafka-topics.sh \
  --list \
  --bootstrap-server localhost:9092
```

# 12. Troubleshooting

This section will become extremely valuable.

Create a table like:

| Problem | Symptoms | Check | Resolution |
|---|---|---|---|
| Container not starting | `docker compose ps` shows exited | `docker compose logs kafka` | Check configuration |
| Port unavailable | Kafka cannot bind port | `ss -lntp` | Free/change port |
| Producer cannot connect | Connection refused | Check advertised listeners | Fix listener configuration |
| Consumer receives nothing | No messages displayed | Check topic/group | Verify producer and topic |
| Docker networking issue | Container cannot resolve Kafka | `docker exec kafka ...` | Check Compose network |

# 13. Common Docker Networking Issue

This deserves its own section because Kafka's **advertised listeners** are particularly important.

Explain:

```text
Inside Docker:
client → kafka:29092

Outside Docker:
client → localhost:9092
```

Then document why you have:

```yaml
KAFKA_ADVERTISED_LISTENERS:
  INTERNAL://kafka:29092
  EXTERNAL://localhost:9092
```

This will save you a lot of troubleshooting later.
