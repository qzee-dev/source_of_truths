#BEFORE CREATING A KAFKA:
We need to identify the actual Kafka broker configuration, the topic names, the consumer group IDs, and understand which services produce messages to which topics and which services consume those messages from those topics.

Better: exclude obvious noise
#git grep -niE 'kafka|bootstrap.servers|bootstrap-server|group.id|groupId|topic|producer|consumer|KAFKA_' -- ':!package-lock.json' ':!yarn.lock' ':!pnpm-lock.yaml'

Also find the service structure
git ls-files | grep -Ei 'docker-compose|dockerfile|\.env|application\.(yml|yaml|properties)|config|kafka|producer|consumer'

if consumer group is not subscribed to a topic, it has no data to read

Topic: transactions
├── Partition 0
├── Partition 1
├── Partition 2
└── Partition 3

Consumer Group: transaction-service-group
├── Consumer 1 → reads Partition 0
├── Consumer 2 → reads Partition 1
└── Consumer 3 → reads Partitions 2, 3

Consumer Group: fraud-service-group
├── Consumer 1 → reads Partition 0
├── Consumer 2 → reads Partition 1
├── Consumer 3 → reads Partition 2
└── Consumer 4 → reads Partition 3


Key differences:
Aspect	Topic Partitions	Consumer Group
What is it?	Physical divisions of a topic for parallel processing	Logical grouping of consumers
Purpose	Enable horizontal scaling, parallelism	Enable independent consumption of same topic
Assignment	Messages distributed to partitions by key or round-robin	Partitions assigned to consumers in the group
Offsets	Each partition tracks its own offset (message position)	Group tracks offsets per partition

## Docker Compose Deployment (Local Dev)

### Step 1: Prepare the Environment

```bash
# Clone and navigate to repo
cd fintech-platform
git checkout develop

# Make scripts executable
chmod +x scripts/deploy-kafka-broker.sh scripts/create-kafka-topics.sh scripts/kafka-consumer-ops.sh

# Review docker-compose structure
cat docker-compose.yaml | grep -A 30 "kafka:"
```

### Step 2: Start Services (Full Stack)

```bash
# Start all services including Kafka
docker-compose up -d

# Verify all services are running
docker-compose ps

# Expected output:
# NAME                     STATUS
# fintech-postgres         Up (healthy)
# fintech-redis            Up (healthy)
# fintech-zookeeper        Up (healthy)
# fintech-kafka            Up (healthy)
# fintech-kafka-ui         Up
# api-gateway              Up
# user-service             Up
# wallet-service           Up
# transaction-service      Up
# fraud-service            Up
# notification-service     Up
# dlq-processor            Up
# ...
```

### Step 3: Create Kafka Topics

```bash
# Method 1: Using docker exec (inside main stack)
docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic transactions --partitions 6 --replication-factor 1 --if-not-exists

docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic transaction-completed --partitions 6 --replication-factor 1 --if-not-exists

docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic fraud-alert --partitions 6 --replication-factor 1 --if-not-exists

docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic payment-initiated --partitions 6 --replication-factor 1 --if-not-exists

docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic payment-completed --partitions 6 --replication-factor 1 --if-not-exists

# DLQ topics (longer retention)
docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic transaction-failed-dlq --partitions 3 --replication-factor 1 --config retention.ms=2592000000 --if-not-exists

docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic payment-failed-dlq --partitions 3 --replication-factor 1 --config retention.ms=2592000000 --if-not-exists

docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic fraud-check-dlq --partitions 3 --replication-factor 1 --config retention.ms=2592000000 --if-not-exists

docker exec fintech-kafka kafka-topics --bootstrap-server localhost:29092 --create --topic notification-dlq --partitions 3 --replication-factor 1 --config retention.ms=2592000000 --if-not-exists

# Method 2: Using the shell script
BOOTSTRAP=kafka:29092 ./scripts/create-kafka-topics.sh
```

        port: 9093

    replicas: 3

      requests:
        memory: "512Mi"
        cpu: "250m"

          memory: "512Mi"

### Common Issues & Solutions

**Issue: Topics not created**
```bash
# Docker Compose - ensure auto-create is disabled
docker exec fintech-kafka env | grep AUTO_CREATE

# Strimzi - check KafkaTopic status
kubectl get kafkatopic -n kafka -o wide
kubectl describe kafkatopic transactions -n kafka
```

**Issue: Consumer lag increasing**
```bash
# Check service is running
docker-compose ps fraud-service

# Check logs for errors
docker-compose logs fraud-service | tail -100

# Verify Kafka connectivity
docker exec fintech-kafka kafka-consumer-groups \
  --bootstrap-server localhost:29092 \
  --describe --group fraud-service-group
```

**Issue: Kafka broker not healthy**
```bash
# Docker Compose
docker-compose restart kafka zookeeper

# Kubernetes
kubectl rollout restart statefulset/fintech-kafka-kafka -n kafka
kubectl wait kafka/fintech-kafka --for=condition=Ready --timeout=300s -n kafka
```

## Quick Reference: Docker Compose vs Kubernetes

| Task | Docker Compose | Kubernetes |
|------|---|---|
| Start Kafka | `docker-compose up -d` | `kubectl apply -f k8s/kafka/` |
| Create topics | `BOOTSTRAP=kafka:29092 ./scripts/create-kafka-topics.sh` | `kubectl apply -f k8s/kafka/kafka-topics.yaml` |
| List topics | `docker exec kafka kafka-topics --bootstrap-server localhost:29092 --list` | `kubectl get kafkatopic -n kafka` |
| View logs | `docker-compose logs -f kafka` | `kubectl logs -f pod/fintech-kafka-kafka-0 -n kafka` |
| Scale consumers | Update `replicas` in docker-compose | Update `replicas` in Deployment |
| Monitor | `http://localhost:8080` | `kubectl port-forward svc/kafka-ui 8080:8080` |
| Stop | `docker-compose down` | `kubectl delete -f k8s/kafka/` |
| Clean up | `docker-compose down -v` | `kubectl delete ns kafka fintech` |

## Summary

**For Local Development:**
Use Docker Compose with single-broker Kafka for simplicity and speed.

**For Production:**
- **On Docker:** Use multi-broker docker-compose.prod.yaml with replication factor 3
- **On Kubernetes:** Use Strimzi operator for production-grade management, auto-scaling, and high availability

Both setups can be managed with the same Kafka scripts by simply changing the bootstrap server address.
